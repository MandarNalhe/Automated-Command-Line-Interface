# WARP.md

This file provides guidance to WARP (warp.dev) when working with code in this repository.

## Project overview

This is a Java 17 Spring Boot application that exposes an HTTP API and static web UI for an "MCP-based CLI automation" assistant (AuCLI). The core flow is:

1. User enters a natural-language request in the web UI (`src/main/resources/static/index.html`).
2. The frontend sends a POST to `/api/generate`.
3. `GenerateController` calls `GenerateTextFromTextInput`, which uses the Google GenAI SDK to convert the prompt into a JSON command matching the MCP schema (`MCPRequest`).
4. The JSON is parsed into an `MCPRequest` object and passed to `MCPHost`.
5. `MCPHost` dispatches the request to one of several local tools (`FileManager`, `ApplicationLauncher`, `CommandPrompt`, `NetworkingCommands`, `MediaTool`) based on the `tool` and `action` fields.
6. Each tool performs OS-level work (file operations, process launch, command execution, basic networking commands, media handling) and returns an `MCPResponse` with a `status` and `message`.
7. The structured `MCPResponse` is sent back to the frontend and rendered in the chat-style UI.

The application is opinionated towards Windows (e.g. `cmd /c start` in several tools) but the planning prompt in `GenerateTextFromTextInput` enforces forward-slash paths in the JSON protocol.

## Code structure and key components

- Entry point
  - `src/main/java/com/mcp/host/mcp_host/McpHostApplication.java` is the Spring Boot entry class (`@SpringBootApplication`) used for all runtime and test bootstrapping.

- HTTP/API layer
  - `src/main/java/com/mcp/host/mcp_host/controller/GenerateController.java` defines the REST API:
    - `POST /api/generate` accepts a JSON body with a single `prompt` field (`InputRequest`).
    - It logs the input, calls the GenAI service to get a JSON command, parses it into `MCPRequest`, invokes `MCPHost.handle`, and returns the resulting `MCPResponse`.
    - Errors are caught and wrapped in an `MCPResponse` with `status = "error"`.

- Prompting / LLM integration
  - `src/main/java/com/mcp/host/mcp_host/Services/GenerateTextFromTextInput.java` encapsulates all interaction with Google GenAI:
    - Injects an `apiKey` property via `@Value("${apiKey}")` and builds a `com.google.genai.Client` each call.
    - Constructs a detailed prompt describing the available tools (`MediaTool`, `ApplicationLauncher`, `FileManager`, `CommandPrompt`, `NetworkingCommands`), allowed actions for each, and strict JSON output requirements.
    - Uses `GenerateContentConfig` with `responseMimeType("application/json")` and model `gemini-2.5-flash` to obtain a JSON string representing an `MCPRequest`.

- Core MCP dispatcher
  - `src/main/java/com/mcp/host/mcp_host/core/MCPHost.java` is the central dispatcher:
    - `handle(MCPRequest request)` uses a `switch` on `request.tool` to route to the relevant tool class.
    - Each case delegates to a static method on a `tools` class, passing `request.action` and `request.parameters`.
    - Unknown tools return an `MCPResponse` with `status = "error"` and a descriptive message.

- Data model
  - `src/main/java/com/mcp/host/mcp_host/model/MCPRequest.java` defines the incoming command schema:
    - Public fields: `tool`, `action`, `parameters` (a `Map<String, String>`).
    - Designed to match the JSON generated by the LLM.
  - `src/main/java/com/mcp/host/mcp_host/model/MCPResponse.java` defines the response schema:
    - Public fields: `status`, `message`.
    - Used both internally between tools and `MCPHost`, and as the API response type.

- Tooling layer (OS integration)
  - `src/main/java/com/mcp/host/mcp_host/tools/FileManager.java`
    - Dispatches on `action` via `handleAction` and implements file/folder operations using `java.io.File` and `java.nio.file.Files`:
      - `listFiles(path)`
      - `createFile(path, fileName)`
      - `deleteFile(path, fileName)`
      - `openFile(path)` using `Desktop.getDesktop().open` when supported
      - `moveFile(source, destination)`
      - `createFolder(path, fileName)` (note: current implementation ignores `fileName` and treats `path` as the full folder path)
      - `copyFile(source, destination)`
    - All operations return `MCPResponse` objects with either a success message or a descriptive error.

  - `src/main/java/com/mcp/host/mcp_host/tools/ApplicationLauncher.java`
    - Provides `openApplication` via `cmd /c start` for launching applications by name or path on Windows.

  - `src/main/java/com/mcp/host/mcp_host/tools/CommandPrompt.java`
    - Executes arbitrary commands by splitting the `command` parameter into tokens and using `ProcessBuilder`.
    - Supports two actions:
      - `Independent`: run commands without changing directory.
      - `Dependent`: run commands with a working directory derived from the `path` parameter.
    - Captures stdout into the `message` field and encodes non-zero exit codes as error responses.

  - `src/main/java/com/mcp/host/mcp_host/tools/NetworkingCommands.java`
    - Wraps network-oriented shell commands under the `network` action.
    - Implementation mirrors `CommandPrompt` (builds a process from a tokenized `command`, waits, and returns output or error with exit code).

  - `src/main/java/com/mcp/host/mcp_host/tools/MediaTool.java`
    - Handles basic media operations using the shell and file system:
      - `openImage(path, fileName)`: probes common image extensions and uses `cmd /c start` when a matching file is found.
      - `playMedia(path, fileName)`: normalizes path separators, appends a default `.mp4` extension when none is provided, and uses `cmd /c start` to invoke the OS default media handler.

- Frontend / static UI
  - `src/main/resources/static/index.html` implements a single-page chat-style UI using Tailwind CSS and Lucide icons.
  - It sends JSON requests to `/api/generate`, renders user and assistant messages, and shows a simple "processing" indicator.

- Tests
  - `src/test/java/com/mcp/host/mcp_host/McpHostApplicationTests.java` is a basic Spring Boot context load test (`@SpringBootTest` with `contextLoads`).

## Build, run, and test commands

All commands below assume the working directory is the project root (where `pom.xml` lives) and use Maven.

### Build

- Full build and package:
  - `mvn clean package`

- Build without running tests:
  - `mvn clean package -DskipTests`

### Run the application

The app is a standard Spring Boot application using the `spring-boot-maven-plugin`.

- Run with Maven (typical dev workflow):
  - `mvn spring-boot:run`

Before running, ensure the Spring property `apiKey` is configured (for example via `application.properties` or JVM/system properties) so `GenerateTextFromTextInput` can authenticate with Google GenAI.

### Tests

- Run the full test suite:
  - `mvn test`

- Run a single test class (example):
  - `mvn -Dtest=McpHostApplicationTests test`

## Working with and extending tools

- To add a new tool:
  - Create a new class under `src/main/java/com/mcp/host/mcp_host/tools/` with static methods accepting an `action` string and a `Map<String, String>` of parameters, returning `MCPResponse`.
  - Add a corresponding `case` branch in `MCPHost.handle` to delegate to the new tool.
  - Update the tool and action descriptions in `GenerateTextFromTextInput` so the LLM is aware of the new capabilities and can emit valid `MCPRequest` JSON.

- To change how existing tools behave:
  - Adjust the concrete implementation in the relevant tool class and, if you change accepted parameters or actions, keep the prompt in `GenerateTextFromTextInput` synchronized so that generated JSON matches runtime expectations.
